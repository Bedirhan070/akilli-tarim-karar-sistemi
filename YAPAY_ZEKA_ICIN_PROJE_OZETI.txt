BÖLÜM 2 — PROBLEM VE MOTIVASYON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEM:
Türkiye'deki çiftçilerin büyük çoğunluğu tarımsal kararlarını (ekim zamanı,
sulama, ilaçlama, hasat) deneyime ve geleneksel yöntemlere dayalı olarak
alır. Hava koşullarındaki ani değişiklikler, don riski, aşırı sıcak, yoğun
yağış gibi etkenler ürün kayıplarına yol açmaktadır. Çiftçilerin büyük
bölümünün gelişmiş meteoroloji sistemlerine ya da tarım danışmanlarına erişimi
yoktur.

ÇÖZÜM:
GPS koordinatlarına dayalı, anlık hava verisi kullanan ve makine öğrenmesi
ile risk analizi yapan, çiftçiye Türkçe olarak somut tavsiye veren, ayrıca
Telegram üzerinden gerçek zamanlı uyarı gönderen bir karar destek sistemi.

HEDEF KİTLE:
- Orta/küçük ölçekli tarım işletmeleri
- Birden fazla tarlası olan çiftçiler
- Tarımsal riski izlemek isteyen kooperatifler ve çiftlik yöneticileri

PROJEYE KATTIĞI DEĞER:
1. Çiftçi tarla başına gitmeden tarlasının risk durumunu öğrenir.
2. Makine öğrenmesi sayesinde sadece "hava sıcak" yerine "bu gün bu ürün
   için risk kritik" bilgisi verilir.
3. Telegram entegrasyonu ile çiftçi her sabah 08:00'de tüm tarlalarının
   özetini alır; kritik durumlarda anında uyarı gelir.
4. Türkiye'nin 81 ili için buğday risk haritası, ülke genelinde tarımsal
   risk dağılımını görselleştirir.

ML yanıt vermediğinde kural tabanlı hesap otomatik devreye girer.

BACKEND TEKNOLOJİLERİ:

  ASP.NET Core 8 / C#
  Gerekçe: Güçlü Dependency Injection desteği, yerleşik JWT authentication
  middleware, Entity Framework Core ile veritabanı entegrasyonu, BackgroundService
  ile arka plan görevleri (günlük bildirim), Swagger/OpenAPI desteği.

  Entity Framework Core 9 (Code-First)
  Gerekçe: Veritabanı şemasını C# sınıflarından otomatik oluşturur.
  Migration sistemi ile şema değişiklikleri sürüm kontrolünde takip edilir.
  Parametrik sorgular sayesinde SQL Injection'a karşı doğal koruma sağlar.

  BCrypt.Net-Next (v4.1.0)
  Gerekçe: Sektör standardı şifre hash algoritması. Her şifre için rastgele
  salt üretir; aynı şifrenin hash'i her seferinde farklı görünür. Kasıtlı
  olarak yavaştır — brute-force saldırılarını zorlaştırır.

  JWT (JSON Web Token) — Microsoft.AspNetCore.Authentication.JwtBearer
  Gerekçe: Stateless kimlik doğrulama. Sunucu oturum bilgisi saklamaz;
  her istek kendi içinde doğrulanır. Mobil ve API istemcileriyle uyumlu.

  Swashbuckle (Swagger) v6.5.0
  Gerekçe: Tüm API endpoint'leri otomatik belgelenir. Geliştirme sırasında
  tarayıcı üzerinden test yapılabilir. Sadece development ortamında aktif.

  IMemoryCache (ASP.NET Core yerleşik)
  Gerekçe: 81 il için hava + risk verisi her istekte yeniden çekilmek yerine
  30 dakika bellekte saklanır. Hem Open-Meteo yük azaltımı hem hız kazanımı.

ML TEKNOLOJİLERİ:

  Python + FastAPI
  Gerekçe: Python ML ekosistemi (scikit-learn, TensorFlow) için standart dil.
  FastAPI, Flask/Django'dan çok daha hızlı; async desteği var; Pydantic ile
  otomatik veri doğrulama; yerleşik Swagger UI.

  scikit-learn (Isolation Forest + Random Forest + StandardScaler)
  Gerekçe: Python ML kütüphanelerinin endüstri standardı. joblib ile model
  serileştirme kolaydır (.pkl dosyaları). Geniş dokümantasyon ve topluluk.

  TensorFlow / Keras (LSTM)
  Gerekçe: Zaman serisi tahminleri için LSTM (Long Short-Term Memory) en
  yaygın kullanılan derin öğrenme mimarisidir. Keras ile model tanımı ve
  eğitimi oldukça kolaydır. .keras formatı modern ve taşınabilirdir.

  pydantic (FastAPI ile birlikte)
  Gerekçe: İstek/yanıt modellerini tip güvenli şekilde tanımlar. Yanlış veri
  tipinde istek gelirse otomatik 422 döner, manuel doğrulama kodu yazmak gerekmez.

FRONTEND TEKNOLOJİLERİ:

  Razor Views (ASP.NET Core MVC şablon motoru)
  Gerekçe: Sunucu taraflı render. İlk sayfa yüklemesinde C# ile HTML üretilir;
  sonraki etkileşimler JS Fetch API ile yapılır. Ayrı bir SPA framework
  (React, Vue) gerekmez; proje tek bir solution içinde kalır.

  Bootstrap 5
  Gerekçe: Grid sistemi ile kolayca duyarlı (mobil uyumlu) tasarım.
  Hazır bileşenler (modal, card, navbar, tablo, form) geliştirme hızlandırır.

  Leaflet.js
  Gerekçe: Açık kaynaklı, ücretsiz interaktif harita kütüphanesi.
  Google Maps API anahtarı gerektirmez. GeoJSON desteği ile Türkiye
  il/ilçe sınırları çizilebilir. Kullanıcı tıkla-koordinat-al akışı mümkün.

DIŞ API'LAR:

  Open-Meteo (open-meteo.com)
  Gerekçe: Tamamen ücretsiz, kayıt gerektirmez, API anahtarı yok.
  GPS koordinatına göre gerçek zamanlı hava verisi verir. Günlük ve saatlik
  veri ayrımı yapılabilir. 7 günlük tahmin dahil. Yüksek güvenilirlik.

  Telegram Bot API
  Gerekçe: Türkiye'de yaygın kullanılıyor. Ücretsiz. Metin, HTML formatlı

  Çiftçilerin akıllı telefon kullanım alışkanlığıyla uyumlu.

  SMTP E-posta
  Gerekçe: E-posta doğrulama en güvenilir hesap onay yöntemidir.
  Herhangi bir SMTP sağlayıcısıyla çalışır (Gmail, Outlook, özel SMTP).

BÖLÜM 6 — MAKİNE ÖĞRENMESİ: MODELLER, EĞİTİM VE ÇALIŞMA MANTIĞI

GİRİŞ VERİSİ (5 özellik — tüm modeller için aynı):
  1. max_sicaklik  — günlük maksimum sıcaklık (°C)
  2. min_sicaklik  — günlük minimum sıcaklık (°C)
  3. yagis         — günlük yağış toplamı (mm)
  4. ruzgar_hizi   — günlük maksimum rüzgar hızı (km/s)
  5. nem           — günlük ortalama bağıl nem (%)

ÖN İŞLEME — StandardScaler (scaler.pkl):
Her model çalıştırılmadan önce bu scaler uygulanır. Eğitim verisinin
istatistiksel özelliklerini (ortalama, standart sapma) kaydeder ve yeni
veriyi sıfır ortalama/birim varyansa normalize eder. Bu olmadan farklı
ölçekteki özellikler (örneğin sıcaklık 20–40 aralığında, nem 0–100 aralığında)
modeli yanlı hale getirir.

─────────────────────────────────────────────────
MODEL 1: Isolation Forest — Anomali Tespiti
─────────────────────────────────────────────────
Endpoint: POST /anomaly
Tür: Gözetimsiz öğrenme (unsupervised)
Dosya: isolation_forest.pkl

Nasıl çalışır:
Isolation Forest, "anormal veri noktaları normal veriden daha az bölme ile
izole edilebilir" prensibine dayanır. Rastgele ağaçlar oluşturur ve her
veri noktasını ayırt etmek için kaç bölme gerektiğini sayar.
  • Bir noktayı izole etmek az bölme gerektiriyorsa → anormal (outlier)
  • Çok bölme gerektiriyorsa → normal (inlier)

Çıktı JSON:
{
  "durum":     "normal" veya "anomali",
  "skor":      ondalık sayı (negatife gidildikçe daha anormal, örn: -0.15),
  "guvenilir": true/false,
  "mesaj":     "Veri normal." veya "Anormal veri tespit edildi!"
}

Tarımsal anlamı:
Belirli bir coğrafya ve mevsim için "bu kadar sıcaklık, nem ve yağış
kombinasyonu beklenen aralıkta mı?" sorusunu yanıtlar. Risk skoru düşük
görünse bile eğer hava koşulları o bölge için alışılmadık ise uyarır.
Örnek: Ağustos'ta Güneydoğu Anadolu'da -5°C → Isolation Forest HEMEN anomali
olarak işaretler, çünkü bu değer eğitim verisinin çok dışındadır.

─────────────────────────────────────────────────
MODEL 2: Random Forest — Risk Sınıflandırma
─────────────────────────────────────────────────
Endpoint: POST /predict
Tür: Gözetimli öğrenme sınıflandırıcısı (supervised classification)
Dosya: random_forest.pkl + label_encoder.pkl

Sınıflar (label_encoder.classes_):
  • "güvenli"       → tarımsal faaliyet için uygun koşullar
  • "riskli"        → dikkatli olunması gereken koşullar
  • "uygun_degil"   → tarımsal faaliyetin ertelenmesi gereken koşullar

Nasıl çalışır:
Onlarca bağımsız karar ağacı eğitilir. Her ağaç:
  a) Eğitim verisinin rastgele bir alt kümesi ile eğitilir (bootstrap)
  b) Her bölme noktasında rastgele özellik alt kümesi kullanılır
Son tahmin tüm ağaçların oylama (majority vote) sonucudur. Bu yaklaşım
tek bir karar ağacının ezberlemesini (overfitting) önler.

Risk skoru hesabı:
  risk_skoru = P("riskli") + P("uygun_degil")
  yani modelin "kötü" olasılığı — 0 ile 1 arasında.

Seviye belirleme:
  risk_skoru > 0.70  → "KRİTİK"  (kırmızı)
  risk_skoru > 0.40  → "ORTA"    (sarı)
  risk_skoru ≤ 0.40  → "GÜVENLİ" (yeşil)

Çıktı JSON:
{
  "sinif":       "güvenli",
  "risk_skoru":  0.22,
  "seviye":      "GUVENLI",
  "renk":        "yesil",
  "olasiliklar": {"güvenli": 0.78, "riskli": 0.10, "uygun_degil": 0.12}
}

─────────────────────────────────────────────────
MODEL 3: LSTM — Zaman Serisi Tahmini
─────────────────────────────────────────────────
Endpoint: POST /forecast
Tür: Derin öğrenme, yinelemeli sinir ağı
Dosya: lstm_model.keras + lstm_scaler.pkl

Giriş formatı: 30 günlük geçmiş veri, her gün 4 değer
  [[max_sic1, min_sic1, yagis1, ruzgar1],
   [max_sic2, min_sic2, yagis2, ruzgar2],
   ...  (30 satır)]

Nasıl çalışır:
LSTM (Long Short-Term Memory) özellikle zaman serisi tahmini için
tasarlanmış bir sinir ağı mimarisidir. Klasik RNN'lerin "uzak geçmişi
unutma" sorununu çözen "bellek kapısı" mekanizması içerir.
Modelin temel mantığı: Geçmiş 30 günün sıcaklık, yağış ve rüzgar
kalıplarına bakarak bir sonraki günün maksimum sıcaklığını tahmin et.

Otoregresif tahmin (sliding window):
Her tahmin bir sonraki günün girdisi olarak kullanılır:
  Adım 1: [gün1..gün30] → gün31 sıcaklığı tahmin et
  Adım 2: [gün2..gün31] → gün32 sıcaklığı tahmin et
  ...  (tahmin_gun sayısı kadar tekrar)

Normalizasyon: lstm_scaler.pkl, 30×4 matrisi normalize eder.
Çıktı ters dönüşüm: lstmscaler.inverse_transform ile gerçek °C değerine.

Not: LSTM modeli Bitlis ili verisiyle eğitilmiştir; çıktıda "sehir: Bitlis"
döner. İleride farklı iller için yeniden eğitim planlanabilir.

Çıktı JSON:
{
  "sehir": "Bitlis",
  "tahmin_gun": 7,
  "max_sicaklik_tahmini": [
    {"gun": 1, "sicaklik": 24.3},
    {"gun": 2, "sicaklik": 25.7},
    ...
  ]
}

─────────────────────────────────────────────────
KURAL TABANLI FALLBACK (ML kapalıysa devreye girer)
─────────────────────────────────────────────────
ML servisi yanıt vermezse C# tarafında kural tabanlı risk hesabı çalışır.
Bu "graceful degradation" prensibidir — sistem hiç yanıt vermemek yerine
daha basit ama çalışan bir yanıt üretir.

Kural eşikleri:
  Sıcaklık min < 2°C     → +0.50 risk (don tehlikesi)
  Sıcaklık max > 38°C    → +0.30 risk (kavurucu sıcak)
  Yağış > 30 mm          → +0.25 risk (yoğun yağış)
  Nem < %30              → +0.20 risk (aşırı kuru)
  Rüzgar > 60 km/s       → +0.20 risk (kuvvetli rüzgar)
  Ürün için fazla sıcak  → +0.22 risk
  Ürün için fazla soğuk  → +0.20 risk
  Ürün için düşük nem    → +0.15 risk
  Ürün için yüksek nem   → +0.12 risk
  Ekim ayı değil         → +0.08 risk
  Toplam: min(hesaplanan, 1.0) ile sınırlandırılır

NEDEN HTTP?   (alternatif karşılaştırması)
─────────────────────────────────────────
  HTTP/REST (seçilen):
  + İki process tamamen bağımsız
  + ML servisi down olsa C# çalışmaya devam eder
  + FastAPI'nin kendi Swagger UI'ı ile ML ayrı test edilebilir
  + İleride ML servisi başka sunucuya taşınabilir (sadece URL değişir)
  + Timeout ve retry politikaları kolay uygulanır
  - Her analiz için ~1-5 ms loopback gecikmesi (ihmal edilebilir)

  ML.NET (alternatif, seçilmedi):
  - scikit-learn Random Forest ve Keras LSTM modellerini desteklemez
  - Modelleri yeniden eğitmek gerekirdi
  - Python kütüphanelerindeki esneklik kaybedilir

  gRPC (alternatif, seçilmedi):
  - HTTP'ye göre daha hızlı ikili protokol
  - Bu ölçekte performans farkı önemsiz
  - Protobuf şema tanımı ek karmaşıklık getirir

  Python.NET / process spawn (alternatif, seçilmedi):
  - Python GIL sorunu
  - Deployment çok karmaşık

Proje katmanlı güvenlik (defense in depth) yaklaşımını benimser:

1. KİMLİK DOĞRULAMA — JWT + Cookie Dual Mode
   ┌──────────────────────────────────────────────────────────────┐
   │ API Endpoint'leri: Authorization: Bearer {token} header      │
   │ MVC Views:         tarim_token adlı HTTP Cookie              │
   │ Tek middleware yapılandırması her iki kanalı da destekler.   │
   └──────────────────────────────────────────────────────────────┘
   JWT parametreleri:
     Algoritma : HMAC-SHA256 (simetrik, anahtar appsettings'de)
     Süre      : 1 saat
     İçerik    : KullaniciId, Email, AdSoyad claim'leri
     Doğrulama : Issuer + Audience + Lifetime + IssuerSigningKey

   401 davranışı:
     /api/* yolları → JSON 401 Unauthorized
     Diğer yollar   → /Home/Login'e yönlendirme (UX için)

2. YETKİLENDİRME — Kullanıcı İzolasyonu
   Her veri erişiminde JWT'den alınan KullaniciId sorgulara eklenir:
     WHERE LokasyonId = X AND KullaniciId = {jwtUserId}
   Başkasının verisine erişmeye çalışan kullanıcı 404 alır.
   Bu, IDOR (Insecure Direct Object Reference) saldırısını önler.

3. ŞİFRE GÜVENLİĞİ — BCrypt
   Düz metin şifre veritabanında ASLA saklanmaz.
   BCrypt özellikleri:
     • Her hash için kriptografik rastgele salt üretilir
     • Rainbow table saldırısını imkânsız kılar
     • Kasıtlı yavaş (cost factor) → brute-force zorlaşır
     • Sabit zamanlı karşılaştırma → timing attack önlenir

4. E-POSTA ONAY SİSTEMİ — 2 Aşamalı Doğrulama
   Kayıt: E-posta onaylanmadan hesap kullanılamaz (EmailOnayli=false)
   Şifre değişikliği 2 aşamalı güvenlik akışı:
     Aşama 1: Yeni şifre "BekleyenSifreHash" alanına yazılır
              (henüz aktif değil, eski şifre geçerli)
     Aşama 2: E-postadaki onay linkine tıklanınca şifre değişir
              Başkası hesaba girse bile şifre değiştiremez

5. TOKEN GÜVENLİĞİ — Farklı Kullanım Senaryolarına Uygun
   ┌──────────────────────┬──────────────────────────────┬──────────┐
   │ Token Türü           │ Oluşturma                    │ Süre     │
   ├──────────────────────┼──────────────────────────────┼──────────┤
   │ E-posta doğrulama    │ Random.Next(100000,999999)   │ 60 sn    │
   │ Şifre sıfırlama      │ Random.Next(100000,999999)   │ 60 sn    │
   │ Şifre onay linki     │ RandomNumberGenerator 256bit  │ 1 saat   │
   │ Telegram bağlama     │ RandomNumberGenerator 256bit  │ 30 dk    │
   └──────────────────────┴──────────────────────────────┴──────────┘
   6 haneli kod: 1.000.000 olasılık × 60 sn süre = brute-force pratiksiz
   256 bit URL token: 2^256 olasılık = kriptografik güvenlik

6. SQL INJECTION KORUMASI — Entity Framework Core
   Tüm sorgular EF Core parametrik sorgu olarak çalışır.
   Ham SQL string birleştirme yapılmamıştır.
   EF Core tüm değerleri SQL parametresi olarak iletir.

7. TELEGRAM WEBHOOK GÜVENLİĞİ
   Her gelen webhook isteği X-Telegram-Bot-Api-Secret-Token header'ı ile
   doğrulanır. Token eşleşmezse 403 Forbidden döner.
   Sahte webhook isteği saldırısını önler.

8. API RATE LIMITING — SemaphoreSlim
   81 il analizi için eş zamanlı istek sınırları:
     Open-Meteo: Maks 15 eş zamanlı istek
     ML Servisi: Maks 10 eş zamanlı istek
   API sağlayıcısının rate limit'ini aşmaz; servisi aşırı yüklemez.

9. SWAGGER KORUMASI
   Swagger UI yalnızca development ortamında aktif.
   Üretimde API şeması dışarıya açılmaz.

10. HSTS (HTTP Strict Transport Security)
    Üretim ortamında HSTS header'ı gönderilir.
    Tarayıcı her zaman HTTPS kullanmak zorunda kalır.

11. TELEGRAM BAĞLAMA — Tek Kullanımlık Token
    Kullanıcı Telegram hesabını bağladıktan sonra token veritabanından
    hemen temizlenir. Aynı token tekrar kullanılamaz.

BÖLÜM 13 — TAVSIYE METNİ ÜRETME MANTIĞI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Proje salt "risk: yüksek" demez; kullanıcıya ne yapması gerektiğini söyler.
Tavsiye metni oluşturma 3 farklı durumda çalışır:

1. KRİTİK SEVİYE:
   "⛔ {konum} — {ürün} için bugün risk yüksek. {risk etkenleri}
   Ekim, ilaçlama ve makine işlerini bugün erteleyin. Yarın tekrar bakın."

2. UYARI SEVİYESİ:
   "⚠️ {konum} — {ürün} için dikkat gerektiren koşullar var. {risk etkenleri}
   Tarlayı gözlemleyin; hava durumu netleşince karar verin."

3. GÜVENLİ SEVİYE (GuvenliTavsiyeMetni — en kapsamlı):
   • Hava durumuna göre farklı açılış cümlesi:
     - Yağışlı: "Hava yağışlı (12.5 mm yağış)"
     - Sıcak: "Hava sıcak (35°C)"
     - Serin: "Hava serin (7°C)"
     - Normal: "Hava ılıman (22°C)"
   • Yağışa göre sulama önerisi:
     - ≥10 mm: "Yağış var; bugün sulama yapmayın"
     - 3-10 mm: "Hafif yağış; toprağı yoklayın"
     - 0: Sıcaklık ve neme göre kişisel sulama tavsiyesi
   • Rüzgara göre ilaçlama uyarısı (>25 km/s)
   • Ürüne özel nem tavsiyeleri

Risk etkenleri listesi (her etken ayrı madde):
  ❄️ Don tehlikesi — gece sıcaklığı -3°C. Çiçekli veya meyveli bitkilerinizi örtün...
  🌡️ Kavurucu sıcak — bugün 42°C. Öğle saatlerinde tarlada çalışmayın...
  🌧️ Yoğun yağış — 45 mm yağdı. Tarlaya traktörle girmeyin...
  🏜️ Hava çok kuru — nem %18, yağış yok. Toprağınızı kontrol edin...
  💨 Kuvvetli rüzgar — 75 km/s. İlaçlama ve gübre sıkma yapmayın...
  🌿 Buğday için hava fazla sıcak — 31°C (üst sınır ~28°C). Sulamayı artırın...
  💧 Buğday susuz kalıyor olabilir — nem %28 (ideal %40 üzeri)...
  🍄 Hastalık riski — nem çok yüksek (%92). Yaprakları kontrol edin...
  📅 Mevsim hatırlatması — Mayıs ayındasınız; Buğday için tipik ekim: Ekim, Kasım...
  🔬 Bu konum için olağandışı hava koşulları tespit edildi.

5 Günlük Sulama Önerisi (ürüne göre özelleştirilmiş):
  Buğday/Arpa:  <5mm → "Sulama gerekebilir"; 5-20mm → "Toprağı kontrol et"; >20mm → "Yeter"
  Mısır:        Sıcakta az yağış → "Sulamayı aksatmayın"
  Diğer ürünler: Nem ve yağış bazlı genel tavsiye

BÖLÜM 15 — PROJENİN GÜÇLÜ YÖNLERİ VE KISITLAMALARI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

GÜÇLÜ YÖNLER:

1. Çok Katmanlı ML Yaklaşımı
   Tek bir model yerine üç farklı model birlikte kullanılır:
   Anomali tespiti (Isolation Forest) + sınıflandırma (Random Forest) +
   tahmin (LSTM). Her model farklı bir soruyu yanıtlar.

2. Graceful Degradation (Zarif Bozunma)
   ML servisi kapalıysa sistem çökmez. Kural tabanlı hesap devreye girer
   ve kullanıcıya bu bilgi iletilir. Yüksek kullanılabilirlik.

3. Gerçek Zamanlı ve Ücretsiz Hava Verisi
   Open-Meteo API anahtarı gerektirmez, ücretsizdir ve GPS bazlı çalışır.
   Her tarlaya özel koordinat ile hassas veri elde edilir.

4. Çift Katmanlı Önbellekleme
   SQL Server + IMemoryCache kombinasyonu gereksiz API çağrılarını engeller.
   Aynı gün içinde tekrar analiz yapılırsa hava verisi anında döner.

5. Kapsamlı Güvenlik Mimarisi
   BCrypt + JWT + 2 aşamalı şifre onayı + token süre sınırları +
   webhook secret token + kullanıcı izolasyonu + HSTS.

6. Gerçek Tarımsal Değer
   Tavsiyeler "risk: yüksek" gibi soyut değil; "don tehlikesi: bitkilerinizi
   örtün, sabah erken kontrol edin" gibi eyleme geçirilebilir metinler içerir.

7. Türkiye Özelinde Tasarım
   81 ilin koordinatları hardcoded. Türkçe arayüz ve bildirimler.
   Türkiye'ye özgü ürünler (buğday, arpa, pamuk, ayçiçeği).

8. Ölçeklenebilir Mimari
   ML servisi bağımsız process olduğu için bağımsız ölçeklendirilebilir.
   Yeni ML modeli eklemek mevcut sistemi bozmaz.

SINIRLAMALAR VE GELECEK GELİŞTİRMELER:

1. LSTM Modeli Bitlis Spesifik
   Mevcut LSTM modeli Bitlis ili verisiyle eğitilmiştir. Diğer iller için
   özelleştirilmiş model veya daha genel bir model eğitimi gereklidir.

2. Eğitim Verisi Şeffaflığı
   ML modellerinin hangi veriyle eğitildiği (tarih aralığı, kaynak, doğruluk
   metrikleri) dokümantasyona eklenmemiştir. Raporda belirtilmesi önerilir.

3. Ürün Çeşitliliği
   6 ürün ile sınırlı. Sebze, meyve, endüstriyel bitkiler eklenebilir.

4. Mobil Uygulama
   Şu an yalnızca web arayüzü. React Native veya Flutter ile mobil uygulama
   özellikle çiftçiler için daha erişilebilir olurdu.

5. Toprak Nemi Sensörü Entegrasyonu
   Sistem hava verisi kullanır; toprak nemi ölçümü IoT sensörlerle yapılabilir.

6. Geçmiş Veritabanı Analizi
   Kullanıcı verimliliğini takip etmek için ürün verimi / kayıp raporlama
   eklenebilir.
